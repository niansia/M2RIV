# MCR 0.4 conformance fixtures

These fixed `PASS`, `WARN`, `INSUFFICIENT_POWER`, `BLOCK`, and `ERROR` reports exercise the portable MCR
consumer boundary without depending on a model, suite, or Merriv-internal runner.
Their executor identifies itself as `example.external-producer`, demonstrating
that the report contract is not restricted to bundles emitted by the Merriv CLI.

Verify one fixture:

```console
merriv mcr verify examples/mcr_conformance/block
```

All five valid decision states return verifier exit code 0 because integrity
verification is separate from evaluation policy and deployment authorization.
The JSON result still surfaces `decision_status`; CI can enforce the bound
evaluation policy, while an organization policy controller owns the separate
deployment `ALLOW`/`DENY` decision.

The `negative/` directory is also normative. Producer conformance must reject a
tampered ID, missing evidence, unknown envelope version, and decision mismatch.
This prevents arbitrary self-consistent reports from being labeled conformant.

Regenerate or check the committed fixtures after a contract change:

```console
python examples/mcr_conformance/generate_fixtures.py
python examples/mcr_conformance/generate_fixtures.py --check
```

The `full/` bundle is different: it is generated by the standard-library-only
[`independent_producer`](../independent_producer/README.md), which does not import
Merriv. It exercises report/evidence/run, manifest/set, release-plan, artifact-diff, and
numerical-diff identities together:

```console
python examples/independent_producer/generate_bundle.py --check
merriv mcr verify examples/mcr_conformance/full
```
